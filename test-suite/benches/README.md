# Benchmark Tests

This directory contains benchmark tests comparing razor-rpc performance with gRPC (tonic) and volo-grpc.

## Prerequisites

- protoc (Protocol Buffers compiler)

```
sudo apt install -y protobuf-compiler
```

- Rust toolchain with tokio support

## Running Benchmarks

### Run gRPC and razor-rpc comparison

```bash
cargo bench -p razor-rpc-test --features "tokio grpc"
```

### Run all benchmarks (including volo)

```bash
cargo bench -p razor-rpc-test --features "tokio grpc volo"
```

### Run specific benchmark

```bash
cargo bench -p razor-rpc-test --features "tokio grpc" -- echo_1kb
```

## Benchmark Scenarios

### echo_1kb

Compares echo service performance with 1KB payload:
- **gRPC (tonic)**: Uses tonic with HTTP/2 transport
- **volo-grpc**: Uses volo framework (currently stub implementation)
- **razor-rpc**: Uses msgpack codec with TCP transport

Default configuration:
- Concurrency: 10 clients
- Requests per client: 100
- Total requests: 1000
- Payload size: 1024 bytes

## Known Issues

### volo-grpc Implementation Issues

The volo-grpc benchmark currently has a stub implementation that returns immediately. Attempting to implement full server/client setup encountered the following issues:

#### 1. Server Creation Issue

**Problem**: `BenchmarkServiceServer` cannot be directly used with `volo_grpc::server::Server::add_service()`

**Error**:
```
the trait bound `BenchmarkServiceServer<BenchmarkServiceImpl>: Service<..., ...>` is not satisfied
```

**Root Cause**:
- `BenchmarkServiceServer` implements `Service<ServerContext, Request<BenchmarkServiceRequestRecv>>`
- But `Server::add_service` requires `Service<ServerContext, Request<BoxBody>>`
- Type mismatch: expected `BenchmarkServiceRequestRecv`, found `BoxBody`

**Attempted Code**:
```rust
let service = BenchmarkServiceImpl;
let server = volo_grpc::server::Server::new()
    .add_service(BenchmarkServiceServer::new(service));
```

#### 2. API Complexity

volo-grpc 0.12 uses a complex type system:
- Generated `BenchmarkServiceServer` is a generic struct over the service implementation
- Service trait uses RPITIT (Return Position Impl Trait In Trait) for async methods
- Requires specific request/response types generated by volo-build

#### 3. Missing Documentation

Limited documentation on:
- How to convert generated `BenchmarkServiceServer` to a generic service
- Proper way to set up a simple server without using the volo-cli tool
- Integration between generated code and `volo_grpc::server::Server`

#### Potential Solutions

1. **Use volo-cli**: The recommended way is to use `volo-cli` to generate the entire project structure
2. **Custom Service Wrapper**: Create a wrapper that converts `BenchmarkServiceServer` to the expected `BoxBody` service
3. **Lower-level API**: Use volo's lower-level service API directly instead of the generated server

#### Current Status

- **tonic (gRPC)**: ✅ Working - ~8 seconds for 1000 requests
- **razor-rpc**: ✅ Working - ~23 milliseconds for 1000 requests (350x faster than tonic)
- **volo-grpc**: ❌ Stub implementation - returns immediately with 0 duration
